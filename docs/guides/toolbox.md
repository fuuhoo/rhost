## 1. 入口

顶栏「工具箱」按钮（SFTP 按钮右侧）。按钮只在存在会话标签时可用；未连接主机时置灰。

弹窗分「Docker」「防火墙」「端口」「公钥」「日志」五个页签，默认打开 Docker；数据按当前活动会话实时采集，同一时间只针对一台主机操作。

## 2. 端口

点击「端口」页签会并行采集监听端口表（`ss` → `netstat` → `lsof` 依次回退）、进程用户表（`ps`）与 docker 容器归属（`/proc/*/cgroup` + `docker ps`，docker CLI 缺席时回退 `config.v2.json`）。容器归属有两条路径：监听进程本身在容器 cgroup 内（host 网络模式等），或端口由 Docker 的 `docker-proxy` 转发——后者按「宿主机监听地址 + 协议 + 端口」反查 `docker ps` 的发布端口映射；两者都匹配不上时才显示 `—`。

| 列 | 说明 |
|---|---|
| 端口 | 监听端口号，按端口升序排列 |
| 协议 | `tcp` / `udp` |
| 监听地址 | 如 `0.0.0.0`、`127.0.0.1`、`[::]` |
| 进程 | 进程名；普通用户视图下只显示自己有权查看的进程 |
| 用户 | 进程属主 |
| 容器 | 容器进程占用或 Docker 转发端口时显示容器名，否则 `—` |
| PID | 进程号 |

顶部支持按端口 / 进程 / 用户 / 容器 / 地址搜索，并按 TCP / UDP 筛选。工具栏右侧显示监听端口总数，筛选中时显示「命中 / 总数」。右上角标注本次实际使用的采集工具与视图级别；以 root 登录（无需 sudo）时同样显示「root 视图」，不再出现「以管理员权限刷新」。容器名可点击复制。

普通用户（非提权）视图下，其它用户的进程信息不可见（`ss -p` 的限制）。点「以管理员权限刷新」以 root 重新采集，可看到全部进程与容器名。

## 3. 防火墙

进页签时自动探测后端，优先级为 **ufw → firewalld → iptables**，并显示当前启用状态与规则列表。

页面顶部是状态条（后端名、已启用 / 未启用，以及 ufw / firewalld 的启停开关），下方四张统计卡分别统计规则总数与允许 / 拒绝 / 其他动作的数量。规则区支持按端口、协议、来源或原始文本搜索，并按动作下拉筛选；「＋ 添加规则」按钮展开新增表单。防火墙处于停用状态时，规则区显示「防火墙已禁用，开启后可管理规则。」。

- **规则列表**：动作（允许 / 拒绝 / 其他）、端口、协议、来源、原始规则文本。可删除的规则右侧显示「删除」；复合规则（ufw 应用名、iptables 链跳转、firewalld 富规则中的 log/limit 等）标为「只读」，避免用错误的命令误删。
- **新增规则**：选择动作与协议，填端口（`80` 或 `8080:8090`）与可选来源（IP / CIDR），提交后立即写入永久配置并 reload（iptables 即时生效）。
- **启用 / 停用**：仅 ufw 与 firewalld 支持。启用前会检查当前 SSH 端口是否已有放行规则，缺失时自动补一条 `SSH端口/tcp`，避免把自己关在门外；停用前会二次确认。
- **iptables**：只管理端口规则，不提供启停（它是包过滤表，不是可启停的服务）；重启后是否保留取决于系统是否保存规则。DOCKER 链等非端口规则只展示、不可删。

来源地址支持 IPv4 / IPv6 与 CIDR，例如 `10.0.0.0/8`、`2001:db8::/32`。端口、协议、动作、来源全部由后端校验后重新生成命令，前端输入不会直接拼进 shell。

## 4. 公钥

「公钥」页签把本地公钥追加到远端用户的 `~/.ssh/authorized_keys`，用于免密登录。

- **公钥来源**：可从「密钥」面板已生成 / 导入的密钥中选择（自动带注释），也可选「手动粘贴公钥」贴入 `ssh-ed25519 AAAA...` 单行文本。
- **目标用户**：默认填当前连接用户，可改成 `root`、`deploy` 等远端已存在用户；home 目录由远端 `getent passwd`（回退 `/etc/passwd`）解析，不假定固定路径。
- **去重**：按算法 + base64 主体比对，已有相同公钥时返回「已存在」，不会重复追加。
- **权限与属主**：`~/.ssh` 不存在时创建为 `700`，`authorized_keys` 为 `600`；以 root 写入其他用户时会把目录属主修正为目标用户，SELinux 环境下自动执行 `restorecon`。
- **安全**：公钥文本由后端校验算法白名单、base64 字符集、单行与长度上限，再重新生成脚本；前端原文不会直接拼进 shell。

## 5. Docker

「Docker」页签分「容器」「镜像」「配置」三个子视图，进入页签时一次采集两类列表（`docker ps -a` 与 `docker images`），工具栏右侧显示当前视图级别。

- **容器列表**：名称（下方附短 ID）、镜像、状态（运行中 / 已停止 / 已暂停等，附 docker 的 Status 文案）、端口映射、创建时间。每个容器可「日志」；运行中的容器另有「终端」「停止」「重启」；已停止 / 已创建 / 已失效的容器可「启动」「删除」。停止、重启与删除前都会弹窗确认，避免误触中断服务。
- **容器日志**：点「日志」进入独立面板，按末尾行数读取（100 / 200 / 500 / 1000 / 2000 / 5000 行，默认 200），可切换是否显示时间戳、随时刷新、一键复制或保存到本地文件（默认文件名 `<容器名>_<时间戳>.log`）。stdout 与 stderr 合并展示；单次最多保留末尾 512 KiB 文本，超出时提示「日志过长，仅显示末尾部分」，下载内容与面板展示一致。
- **容器终端**：点「终端」在弹窗内打开容器内交互终端（`docker exec -it`，优先 `bash`，没有时回退 `sh`）。终端复用 xterm 与当前配色/字体设置，支持窗口缩放与中文输入；无 docker socket 权限时会按需提权。关闭面板、断开连接或关闭标签时终端一并销毁。
- **镜像列表**：仓库:标签（悬空镜像回退显示镜像 ID）、短镜像 ID、大小、创建时间；每一行可「导出」「删除」。镜像视图工具栏提供「拉取镜像」与「导入镜像」。
- **镜像拉取**：填完整镜像地址（支持 Docker Hub、`ghcr.io`、私有仓库与带端口的主机，如 `harbor.example.com:5000/team/app:1.0`），执行 `docker pull`；可另填自定义标签：只填标签名（如 `v2`）时沿用所拉镜像的仓库名，填完整引用（如 `myrepo/app:v2`）时按原样打标签。拉取成功但打标签失败会单独提示，镜像本身已留在本地。
- **镜像导出**：默认「保存到本地」，用系统对话框选择本地文件（另存为）或本地文件夹（落为 `<文件夹>/<仓库>_<标签>.tar`）。后端先在远端 `docker save` 到 `/tmp` 临时 tar，再经 SFTP 下载到本地并删除临时文件，面板显示下载进度。切到「保存到远端」则直接填远端路径，目标已存在时先确认覆盖。完成后提示 tar 大小与路径。
- **镜像导入**：默认「本地文件」，可选单个 / 多个本地 tar（`docker load` 支持的 `.tar`、`.tar.gz` 等），或选择本地文件夹自动收集其中的镜像文件；后端逐个经 SFTP 上传到远端临时文件后执行 `docker load`，完成后删除临时文件，成功后自动刷新镜像列表。切到「远端路径」则读取远端已有的 tar。可选填自定义标签（仅单个文件时可用），导入后把载入的镜像再打一份标签；由于 tar 内仓库名无法预先得知，导入的自定义标签需填写完整引用（如 `nginx:my-tag`）。文件不存在或格式错误会给出明确说明。
- **筛选**：搜索框匹配名称 / 镜像 / 状态 / 端口 / ID（镜像视图匹配仓库 / 标签 / ID / 大小），容器另可按状态下拉筛选（运行中 / 已停止 / 已暂停 / 其他）。工具栏显示「命中 / 总数」。
- **删除确认**：删除容器与镜像均二次确认；删除容器不会自动清理数据卷。运行中的容器需先停止再删除，避免误删。
- **配置（daemon.json 可视化）**：配置页把远端 `/etc/docker/daemon.json` 拆成三块可视化编辑与展示——「数据目录」对应 `data-root`（须为绝对路径，例如 `/home/docker1`；留空表示使用 Docker 默认目录，保存时移除该项），「镜像加速源」对应 `registry-mirrors`（最多 10 条，须以 `http://` / `https://` 开头），「其他配置项」只读展示其余键及其 JSON 值。页面底部实时预览保存后的完整 daemon.json，预览区本身也是可编辑的 JSON 编辑器，保存时以预览内容为准；手工编辑后再改上方表单，会同步更新对应的 `data-root` / `registry-mirrors` 键，可随时「撤销编辑」回到表单生成的内容。
- **保存内容**：前端提交预览编辑器里的完整 daemon.json。后端先解析校验：顶层必须是 JSON 对象；`registry-mirrors` 若存在须为 `http(s)` 字符串数组（最多 10 条，去重，空数组视为移除该项）；`data-root` 若存在须为绝对路径（空字符串视为移除该项）；其余键不做限制、按原样写入；内容超过 64 KiB 拒绝。写入前以时间戳备份原文件，再写临时文件并原子替换，最后重启 Docker；重启失败会自动还原备份并给出失败输出。
- **权限**：Docker socket 通常仅 root 或 `docker` 组可访问。读取失败时先尝试免密 sudo，再按需询问 sudo 密码；以 root 视图读取时工具栏会标明。配置读取遇到 `daemon.json` 不可读时同样会走提权重试；保存加速源与重启 Docker 需要 root。
- **安全**：容器名 / ID、镜像引用、自定义标签、远端 tar 路径、本地文件路径、镜像源地址与 `data-root` 都由后端按白名单校验，再重建 `docker start/stop/restart/rm/rmi/pull/tag/save/load/exec` 命令与写入脚本，前端文本不会直接拼进 shell；日志下载与镜像本地导出由后端写入用户选定的本地路径，内容即面板已读取的日志 / 远端 tar；配置保存的整份 JSON 来自前端预览编辑器，后端先解析校验 JSON 结构以及 `registry-mirrors`、`data-root` 的取值，规范化后再重建写入脚本。

## 6. 系统日志

「日志」页签查看远端主机的系统日志。不同系统的日志路径差异很大，进页签时先探测远端实际可用的来源，再按来源读取末尾若干行，远端只跑只读命令（`tail` / `journalctl` / `log show`），不经终端 PTY。

**来源探测与优先级**：探测 `uname`、`/etc/os-release`、`journalctl` 与 `log` 是否可用，以及一批常见文本日志文件是否存在、当前用户是否可读，按以下顺序组装来源下拉：

1. **journald 优先**：存在 `journalctl` 时给出「系统日志（journald）」与「内核日志（journald，`-k`）」两项。systemd 发行版用 journald 统一收纳日志，与具体发行版的路径差异无关，因此排在最前。
2. **文本日志文件回退**：列出检测到的 `/var/log` 文件，按文件名标注发行版归属与内容范围：

   | 文件 | 说明 |
   |---|---|
   | `/var/log/syslog` | 综合系统日志（Debian/Ubuntu） |
   | `/var/log/messages` | 综合系统日志（RHEL/CentOS/Fedora） |
   | `/var/log/auth.log` | 认证与授权日志（Debian/Ubuntu） |
   | `/var/log/secure` | 认证与授权日志（RHEL/CentOS/Fedora） |
   | `/var/log/kern.log`、`/var/log/dmesg` | 内核日志 / 内核环形缓冲 |
   | `/var/log/cron`、`/var/log/daemon.log`、`/var/log/user.log` | 计划任务 / 守护进程 / 用户进程 |
   | `/var/log/maillog`、`/var/log/mail.log`、`/var/log/boot.log` | 邮件 / 启动 |

3. **macOS 统一日志**：仅当系统为 Darwin 且存在 `log` 命令时，额外给出「统一日志（log show）」（最近 1 小时）；`/var/log/system.log` 若存在也按文件来源列出。

工具栏显示探测到的发行版友好名（`PRETTY_NAME`，缺失回退 `NAME`/`ID`）。当前用户读不了的来源仍会列出，读取时按需提权。

**读取与筛选**：

- 末尾行数可选 100 / 200 / 500 / 1000 / 2000 / 5000（默认 200），随时「刷新」。单次最多保留末尾 512 KiB 文本，超出提示「日志过长，仅显示末尾部分」。
- 搜索框按日志内容过滤；级别下拉按关键词把每行归类为错误 / 警告 / 信息 / 调试 / 其他（错误含 error/critical/fatal/fail/panic 等，警告含 warn/warning，信息含 info/notice，调试含 debug），错误行标红、警告行标黄、调试行置灰。工具栏显示「命中 / 总数」。级别归类是客户端关键词启发式，对 journald 与文件来源一致生效。
- **时间段**：「时间」行用两个文本框设起始 / 结束，格式 `YYYY-MM-DD HH:MM[:SS]`（日期与时间之间空格或 `T` 均可，占位符即 `YYYY-MM-DD HH:MM`），可只填一端，「清除」一键复位，与关键字、级别筛选叠加生效。journald 来源把时间段交给服务端 `journalctl --since/--until` 精确查询（能查到当前末尾行窗口之外的历史，按主机本地时区解释）；文件来源与 macOS 没有等价的原生时间查询，只在已加载的末尾行内按行首时间戳做客户端过滤——传统 syslog 时间戳不带年份，按当前年份推断、若落在未来则回退一年（跨年日志）。客户端过滤按日志行所示的本地墙钟时间比较，不做时区换算，主机与本机时区不一致时以日志所示时间为准；结束时间只写到分钟时含整分钟。时间参数由后端严格校验为 `YYYY-MM-DD[ HH:MM[:SS]]` 后重建命令。
- **排序**：「最旧在前 / 最新在前」切换显示顺序（日志本按时间序读取，切换即反转）；复制与下载跟随当前排序。
- **实时跟随**：勾选「实时」后每 3 秒自动刷新；视图本就贴底时滚到最新，正在回看历史时不会被打断；页面不可见时暂停轮询。切走页签、关闭弹窗或断开连接即停止。
- **复制 / 下载**：作用于当前筛选后的视图（所见即所得）；下载用系统对话框选本地路径，默认文件名 `<来源>_<时间戳>.log`，内容与面板展示一致。

**权限与安全**：`/var/log/secure`、`auth.log` 等受保护日志普通用户读不了时，先试免密 sudo，再按需询问 sudo 密码（见下节）。来源 id 与文件路径由后端校验后重建命令：文件来源仅允许 `/var/log/` 下的绝对路径（拒绝 `..` 与控制字符），journald / macOS 来源用固定命令，前端文本不会直接拼进 shell。

## 7. sudo 权限

防火墙读取与变更、端口的「管理员视图」、把公钥写入其他用户、读取受保护的系统日志（如 `/var/log/secure`、`auth.log`），以及无 Docker socket 权限时读取 / 操作容器与镜像、读取 `daemon.json`、保存 daemon.json 与重启 Docker 需要 root：

1. 先尝试免密 `sudo -n`（已配置 NOPASSWD 或本身是 root 时无感）；
2. 不可用时弹窗询问 sudo 密码，校验通过后执行，并在本会话内复用；
3. 密码只存在于前端内存（按后端会话 id 隔离），**不写入配置、不写钥匙串、不落日志**；
4. 断开、关闭标签、重连时立即清除缓存；
5. 密码错误会立即丢弃缓存并提示重试；主机 sudo 要求 TTY、或未安装 sudo 时会给出明确说明。
6. 容器交互终端拥有独立 PTY：需要口令时会先用 `sudo -v` 在终端内预热凭据，再以 `sudo -n` 启动容器内 shell，口令不会出现在命令行、回显或日志里；已配置 NOPASSWD 时完全跳过该步骤。

## 8. 支持范围与限制

| 后端 | 读取规则 | 增删 | 启停 | 备注 |
|---|---|---|---|---|
| ufw | 支持 | 支持 | 支持 | 应用配置（如 `Apache Full`）只读 |
| firewalld | 支持 | 支持 | 支持 | 仅默认区域的端口与可还原富规则；区域 / 服务 / ipset 不在本工具范围 |
| iptables | 支持 | 支持（端口规则） | 不支持 | 仅 `INPUT` 链；重启持久化由系统自行管理 |
| 其它 | 提示未检测到 | — | — | nftables 原生配置、云厂商安全组不在本工具范围 |

- 端口采集依赖远端存在 `ss`、`netstat` 或 `lsof` 之一；都不存在时会提示无法读取。
- 公钥写入依赖远端存在 `getent` 或可读的 `/etc/passwd`；目标用户须为 POSIX 风格用户名（字母 / 下划线开头，允许数字、`_`、`-`、`.`）。
- Docker 管理依赖远端存在 `docker` CLI（使用 `PATH` 中的 `docker`）且 daemon 可连接；普通用户不在 `docker` 组时需要 sudo。覆盖容器与镜像的查看、容器日志（复制 / 下载）、容器内交互终端、启停 / 重启 / 删除、镜像拉取 / 打标签 / 删除与 tar 导入导出，以及 daemon.json 的 `data-root` / `registry-mirrors` 可视化配置；compose 栈、卷、网络不在本工具范围。
- 镜像导入导出支持「本地文件 / 文件夹」与「远端路径」两种方式：本地模式经 SFTP 在远端 `/tmp` 中转（临时文件用完即删，导出临时文件可能由 root 创建、由同一提权通道清理），远端模式直接读写远端 tar；中转只经过当前 SSH 会话，不经过第三方服务。
- daemon.json 配置页可视化编辑 `data-root` 与 `registry-mirrors`，保存预览区可直接编辑完整 daemon.json（含 `log-driver` 等其他配置项），保存以预览内容为准。修改 `data-root` 不会自动迁移已有的镜像与容器数据，需自行停止 Docker 后迁移目录。
- 容器日志来自 `docker logs`，因此只包含容器主进程输出；滚动日志文件、Docker 崩溃日志与 journald 不在本工具范围。
- 系统日志依赖远端存在 `journalctl`、`/var/log` 下的文本日志文件或 macOS `log` 之一；都不存在时提示未检测到可用来源。文件来源仅限 `/var/log/` 目录，wtmp/btmp/lastlog 等二进制登录记录不在范围；journald 的按服务单元（`-u`）过滤与 macOS `log show` 的谓词过滤暂不提供（macOS 统一日志固定取最近 1 小时）。时间段查询仅 journald 走服务端 `--since/--until`，文件来源 / macOS 为已加载窗口内的客户端过滤。级别筛选为客户端关键词归类，非 syslog 优先级精确匹配。
- 容器终端与端口扫描一样需要额外 exec 通道：堡垒机等单通道会话不支持，会直接返回错误，不会影响现有终端。
- 容器终端依赖镜像内存在 `sh`（优先 `bash`）；distroless 等无 shell 镜像无法进入。
- 防火墙变更会立即影响线上流量，请在操作前确认规则与来源网段；停用防火墙等于按默认策略暴露端口。

## 9. 日志

工具箱的后端埋点使用 `toolbox.*` 事件（目标 `toolbox`）：

| 事件 | 说明 |
|---|---|
| `toolbox.ports.list` | 端口采集完成：工具、数量、是否提权、耗时、是否超时 |
| `toolbox.firewall.list` | 防火墙状态与规则读取完成：后端、启用状态、规则数 |
| `toolbox.firewall.change` | 规则新增 / 删除 / 启停：操作类型、端口、协议、来源有无、是否自动放行 SSH |
| `toolbox.pubkey.deploy` | 公钥写入 / 已存在：目标用户、密钥类型、结果路径、是否新增、是否提权 |
| `toolbox.docker.list` | 容器 / 镜像读取完成：容器数、运行中数、镜像数、是否提权、耗时、是否超时 |
| `toolbox.docker.action` | 容器启停 / 重启 / 删除与镜像删除：对象类型、动作、目标、是否提权、退出码、耗时 |
| `toolbox.docker.logs` | 容器日志读取：容器、行数、是否带时间戳、字符数、是否截断、是否提权、耗时 |
| `toolbox.docker.transfer` | 镜像导入 / 导出（含本地中转）：op（pull/import/export/import_local/export_local）、镜像或远端路径、本地文件路径、tar 大小与字节数、成功与否、是否提权、耗时、是否超时 |
| `toolbox.docker.config` | 配置读取与保存：读取记录版本、daemon.json 是否可读、键列表、`data-root`、镜像源条目；保存记录写入的键列表、字节数、是否重启成功（失败另记退出码、超时与错误） |
| `toolbox.docker.terminal` | 容器终端打开 / 关闭：容器、终端尺寸、sudo 模式（无 / 免密 / 口令）、会话结果 |
| `toolbox.syslog.sources` | 系统日志来源探测：系统名、发行版、来源数、是否含 journald、耗时、是否超时 |
| `toolbox.syslog.read` | 系统日志读取 / 保存：来源 id、行数、时间段（since/until）、字符数、是否截断、是否提权、耗时；保存记本地路径与字节数 |

日志只记录操作元数据，**绝不记录 sudo 口令、公钥内容与容器日志正文**。

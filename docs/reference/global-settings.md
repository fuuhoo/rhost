## 1. 入口

- 快捷键：`⌘,`
- 菜单：应用菜单 → 设置

设置项持久化到 `app_config.json` 的 `settings` 节（日志相关字段归入 `logs` 节），修改后即时写入。

## 3. 终端

![终端设置](../assets/settings-terminal.png)

### 3.1 字体与配色

| 设置项 | 取值 | 默认值 | 说明 |
|---|---|---|---|
| 等宽字体 | 随包内置的 DejaVu Sans Mono / Liberation Mono / JetBrains Mono / Monospace，或系统已安装字体，或系统等宽 | DejaVu Sans Mono | 默认取 FinalShell 终端的同名字体。四款内置字形不依赖系统安装：DejaVu Sans Mono、Liberation Mono 以官方 TTF 发布（`frontend/public/fonts/`，许可证见 `frontend/public/DejaVuSansMono-LICENSE.txt`、`frontend/public/LiberationMono-LICENSE.txt`），JetBrains Mono（OFL 1.1，`frontend/public/JetBrainsMono-OFL.txt`）与 Monospace 以 woff2 随包发布；下拉里的「Monospace」即微软终端字体 Cascadia Code，按显示名约定不露出原名。其余候选需系统安装，未安装会在下拉里标注。字体栈是逐级按字符回退的：所选字体缺失 → 系统等宽（Menlo/Consolas 等）→ Nerd 打补丁字体（装了才命中，用于补上内置字体都没有的 Powerline 私有区字形，agnoster/powerlevel10k 提示符才不是豆腐块）→ 中文等宽（Sarasa/思源等宽 → 苹方 → 微软雅黑）→ 通用 monospace |
| 字号 | 10~20（px） | 14 | 终端字体大小 |
| 行高 | 100~200（%） | 125 | 行高倍数 |
| 字重 | 300 / 400 / 500 / 700 | 400 | 字体粗细。内置字体里只有 JetBrains Mono 备齐 300/400/500/700 四档真字形；DejaVu Sans Mono、Liberation Mono、Monospace 只发布常规与粗体，选 300/500 时就近取一档，差额由浏览器合成描边 |
| 配色方案 | FinalShell 经典 / 墨蓝（GitHub 系）/ Solarized / Gruvbox / Catppuccin / Tokyo Night / Nord / One Dark / Dracula | FinalShell 经典 | 一个方案是一族配色，决定终端正文与 16 色 ANSI、光标与选区、连接时的服务器状态面板文字、查找高亮以及设置页预览；用它的深变体还是浅变体由「背景颜色」决定，方案名不再承诺底色。取值逐值来自上游而非按截图估色：经典取自 FinalShell 内置 Default 主题（其程序包内 `finalshell.jar` 的 `resources/theme/Default.json`），深变体是 `#002945` 底 + 纯白正文 + 高饱和 ANSI、对比度最高；墨蓝是 rhost 自有的低饱和方案，浅变体走 GitHub Light 系（高饱和 ANSI 在近白上会糊成一片）；其余七家取 Alacritty 官方主题仓库 `alacritty-theme` 的对应 TOML，上游未给的字段（光标/选区/查找装饰）按同一份推导规则补齐，规则与来源写在 `frontend/src/lib/termThemes.ts` 头部。下拉里标「无浅底」的方案没有浅色变体，背景颜色选「浅色」时自动回落墨蓝浅底 |
| 背景颜色 | 跟随界面 / 深色 / 浅色 / 蓝色 | 深色 | 与配色方案正交：方案管前景与 16 色，这里管终端底色取哪一档。「跟随界面」随界面主题深浅取本方案变体；「深色」「浅色」恒取对应变体；「蓝色」把底色钉在 FinalShell 深蓝 `#002945`（配任意方案的深变体 ANSI）。所选方案没有浅色变体而背景为浅时，回落墨蓝的浅变体——深变体的白前景在近白底上不可读。默认「深色」而非「跟随界面」：浅色界面下也要保持 FinalShell 那套深蓝观感。**开启背景图片时本项不再作用于终端**：衬底只剩图片本身，墨色改由图片明暗决定（见下一行） |
| 背景图片 | 开 / 关 + 内置壁纸 / 本地图片 | 关，无图片 | 开启后图片即终端衬底（「背景颜色」不再掺进来，衬底由图片自身提供），文字始终在图片之上；正文字色按图片的平均亮度在所选方案的深/浅变体里自动取对比度更高的一套——深蓝壁纸出白字（与 FinalShell 一致），换了亮图就自动换回深色墨。开关关掉保留已选图片。行内一排缩略图即 FinalShell 的「图片列表」：五张内置壁纸（`frontend/public/bg/`，逐张取自 FinalShell 程序包 `finalshell.jar` 的 `resources/images/bg1-5.jpg`，原图未改，bg1 深蓝渐变是它的默认背景）点一下就用，选中项描边高亮；「本地图片…」走系统文件对话框。两种来源在配置里的存法不同：内置存 `builtin:bg3.jpg` 引用（图随包发布，不进配置），本地图按最长边 1920 缩放重编码 JPEG、压到 1.2MB 以内后整段存 dataURL（背景在文字之下，压缩痕迹不可见；原始文件超过 20MB 由后端直接拒绝），因此配置导出/导入会带上自定义壁纸、换机即恢复。与 FinalShell 的两处主动偏离：没有「最近使用」列表、本地图片存配置而非存文件路径；另外 FinalShell 的白字是写死在主题里的（配亮图就会糊），这里按亮度回退 |
| 图片浓度 | 20~100（%） | 100 | 图片层不透明度：100% 即完全以图片为背景（FinalShell 的观感）。图片层半透明时底下必须有东西，这里垫的是**图片自身的平均色**而不是窗口玻璃——浅色界面的玻璃近乎纯白，60% 的深蓝壁纸叠上去就成了一层灰膜（用户报的「感觉蒙了一层东西」）；所以调低浓度是向图片主色压平，色相始终留在壁纸里 |
| 图片模糊 | 0~10（px） | 0 | 只模糊图片层，文字始终清晰（对应 FinalShell 的 `bg_img_blur_level`，其默认 4）；图上有细节或与终端内容抢注意力时调高 |

> 终端底色不写死在主题里：xterm 主题保持 `background` 透明，容器底色由「方案 × 背景颜色」经 CSS 变量 `--term-surface` 提供，
> 因此仍受「背景不透明度」控制、可透出桌面形成毛玻璃；`--term-bg`（深色 `#002945`、浅色 `#f7f9fb`）只作首帧与未挂载终端外表面的兜底。
> 开启背景图片时「背景颜色」整条退出：`--term-surface` 改取图片自身的平均色（`stores/settings.ts` 的 `termBgImageTint`），
> 取哪一档变体则由图片平均亮度决定（同文件的 `termInkBg`）——两者共用一次 32×32 采样、按图片地址缓存，测出前衬底暂留透明。
> 前提是 `style.css` 把 xterm 自带样式里写死成纯黑、且铺满终端区的 `.xterm-viewport` 强制改成透明——主题的 `background` 只落到它的子节点内联样式上，少了这条覆盖，配色方案与背景颜色都会表现为黑屏。
> 切换方案、背景颜色或背景图片三项都会热更新已打开的终端；服务器状态面板按连接时解析出的配色着色，之后改配色不影响已画出的那一屏。

### 4.4 安全与完整性

| 设置项 | 取值 | 默认值 | 状态 |
|---|---|---|---|
| SFTP 会话空闲超时 | 秒，0 不关闭 | 300 | ✅ 只关 SFTP 子通道，SSH 终端不受影响；有在飞任务时顺延，下次传输自动重建通道 |
| 传输完成后 Hash 校验 | 开 / 关 | 关 | ✅ 两侧整文件各算一次 SHA256 比对，0 字节文件跳过 |
| 文件黑名单 glob | 一行一条 | `.DS_Store`<br>`Thumbs.db` | ✅ 仅支持 `*` 与 `?`，按文件名（不含目录）大小写不敏感匹配，只作用于上传方向；命中则不创建任务 |

### 4.5 浏览

| 设置项 | 取值 | 默认值 | 状态 |
|---|---|---|---|
| 显示隐藏文件 | 开 / 关 | 关 | ✅ 本地与远端文件树同时生效 |
| 显示本机文件栏 | 开 / 关 | 关 | ✅ 关闭后 SFTP 只保留远端一栏：本机侧的新建/重命名/删除按钮与双栏宽度分隔线一并隐藏（分隔线是 `sftpLocalRatio` 的唯一入口，随本机栏一起消失）。上传改为把文件或文件夹直接拖进文件区（可多选、文件夹整棵递归、空目录同样复刻），下载落点由文件区顶栏「下载到」选择。重新打开即恢复双栏与原有全部本机操作 |
| 编辑器命令 | 命令 + 参数，留空自动探测 | 空 | ✅ 远端文件右键「用编辑器打开」拉起的程序。可从「选择程序」里挑（后端探测系统中可打开文本文件的程序：PATH 上的已知编辑器 + macOS 的 `.app` 包 / Linux 的 `.desktop` 入口 / Windows 的 `App Paths` 注册表项），也能「按路径选择」直接指到某个程序或应用包，或自己写命令加参数。留空按 `code` → `codium` → `cursor` → 系统默认顺序探测。按空白拆分并支持引号 / 反斜杠转义，文件路径追加在参数末尾且作为独立 `execve` 参数传入（远端文件名不可信，不经 shell 展开）；不读 `EDITOR` 环境变量——GUI 进程没有 TTY，`vim` 这类全屏编辑器打不开 |

拖拽上传的落点恒为**远端当前目录**；落在文件区之外（如 AI 聊天附件区）不会被当成上传。路径由 Tauri 的 webview 级拖放事件给出（`frontend/src/lib/fileDrop.ts` 的 `watchFileDrop` 做落点判定，`DockPanel.vue` 的 `dropZone` / `uploadLocalPaths` 建任务），目录骨架创建见 `src-tauri/src/ssh/sftp.rs` 的 `sftp_mkdir_all`。

编辑器协同（含批量）：取回临时副本 → 编辑器保存 → 自动回写，回写冲突策略是「远端有变化就弹窗，不静默覆盖」，见 `DockPanel.vue` 的 `openInEditor` / `syncEditWatch` 与 `src-tauri/src/localfs.rs` 的 `open_in_editor` / `list_text_editors` / `local_files_meta`、`src-tauri/src/ssh/sftp.rs` 的 `sftp_fetch` / `sftp_stat`；单文件上限 32 MB（`EDIT_FETCH_MAX`）。操作说明见 [SFTP 文件传输](../guides/sftp.md) 的 2.6。

## 8. 命令模板

| 设置项 | 取值 | 默认值 | 说明 | 状态 |
|---|---|---|---|---|
| 自定义命令 | 名称 + 命令，可多条 | 空 | 「执行命令…」面板（`⌘K`）末尾的自定义分组：选中一条即把命令写入当前活动终端并回车执行 | ✅ |

- 全局一份，不区分主机与分组；条目顺序即面板里的展示顺序，调整顺序靠删除后重加。
- 名称留空时面板用命令原文当标题；命令为空的行保存时丢弃（面板同样跳过这类行）。
- 条目右侧回显命令原文，超长截断，鼠标悬浮看全文。
- 没有在线会话时条目置灰，键盘导航跳过；一条模板都没配时面板保留一行引导项，点它直接跳到本页。
- 单行命令直接写入终端并补一个回车；多行命令以整块粘贴（bracketed paste）一次性提交，避免中间换行被 shell 逐行执行。
- 与 AI 命令提案的分工：模板是自己写死的常用命令，选中即执行、**不做二次确认**（带确认与高危关键词的是 AI 提案，见 §10.6），所以只应放可直接执行的命令。
- 命令按终端输入通道写入，与手工敲入等价：远端 shell 怎么解析就怎么执行；Rust 侧只负责持久化，不做变量替换（当前无占位符）。

### 10.3 技能 SKILL

技能为用户维护的 Markdown 文件，注入对话上下文供模型参考。**文件内容将随对话发送给模型服务商**。

| 设置项 | 取值 | 默认值 | 说明 | 状态 |
|---|---|---|---|---|
| 启用技能注入 | 开 / 关 | 开 | 将技能目录下的 `.md` 文件注入对话上下文 | ✅ |
| 技能目录 | 按钮 | — | 在系统文件管理器中打开 `app_config_dir/ai/skills/`；目录首次打开时自动创建 | ✅ |
| 技能文件 | 逐条开关 | 全部启用 | 文件名（含扩展名）为稳定标识，重命名文件后需重新设置 | ✅ |

文件格式与注入规则：

- 仅扫描目录顶层的 `.md` 文件（扩展名小写比较）；跳过隐藏文件（`.` 开头）、子目录与符号链接；按文件名字典序注入；
- 可选 frontmatter 声明 `name` / `description`（`---` 围栏内逐行 `key: value`），缺省时名称取文件名去扩展名；
- 单文件超过 8KB 时只注入前 8KB 并在标题标注「内容已截断」；每类合计注入预算 16KB（UTF-8 字节），超限丢弃靠后文件；
- 发送对话时实时读取，无需重启应用。

| 设置项 | 取值 | 默认值 | 说明 | 状态 |

| 规则目录 | 按钮 | — | 在系统文件管理器中打开 `app_config_dir/ai/rules/`；目录首次打开时自动创建 | ✅ |
| 规则文件 | 逐条开关 | 全部启用 | 文件名（含扩展名）为稳定标识，重命名文件后需重新设置 | ✅ |

### 10.5 记忆 Memory

记忆为应用从对话中自动提取（或用户手动添加）的用户级事实，全局存储、全局注入。**记忆内容将随对话发送给模型服务商**。

| 设置项 | 取值 | 默认值 | 说明 | 状态 |
|---|---|---|---|---|
| 启用跨会话记忆 | 开 / 关 | 开 | 开启后，智能体将从对话中提取你的偏好与项目上下文，跨会话生效 | ✅ |
| 记忆条数上限 | 10~1000 | 100 | 超出后自动淘汰最旧的记录 | ✅ |
| 手动添加记忆 | 文本 + 按钮 | — | 直接写入一条记忆（≤ 200 字符），随对话注入 | ✅ |
| 记忆列表 | 逐条删除 | — | 展示内容、创建时间与来源（手动添加 / 全局对话 / 会话），可逐条删除 | ✅ |
| 清空记忆 | 按钮 | — | 删除全部记忆条目（二次确认），不可恢复 | ✅ |

存储与注入规则：

- 存储于 `app_config_dir/ai/memory/memory.json`（原子写），不参与配置导入导出；解析失败按空记忆降级，不影响对话；
- 对话正常完成后后台自动提取：未提取新增内容 ≥ 4000 字符时触发，已摘要部分不重复提取；提取失败静默，下轮完成后重试；
- 单条记忆 ≤ 200 字符；注入合计预算 8KB（UTF-8 字节），超限时从最旧开始丢弃并标注；
- 提取指令禁止记录密码、私钥、API Key、Token 等敏感凭据。
